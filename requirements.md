# Project: Go Links

Build a small internal URL shortcut service.

## Examples

- `go/design-system`
- `go/oncall`
- `go/payroll`

## Requirements

Users should be able to:

- Create a shortcut
- View existing shortcuts
- Visit a shortcut and be redirected

---

## Technical Expectations

- Use **TypeScript**
- Choose any frameworks, libraries, and architecture you think are appropriate.
- Engineering judgment is more important than framework choice.

---

## Time Limit

Spend **no more than 60 minutes** if building this specifically for the interview.

The goal is not a polished production application. Focus on thoughtful engineering decisions and explain what you would do next if given more time.

---

## What They're Looking For

Some things they like seeing:

- Thoughtful user experience
- Clear API design
- Accessibility
- Maintainable code
- Good project organization
- Error handling
- Validation
- Observability (logging, diagnostics, request IDs, etc.)
- Good documentation
- Appropriate library choices
- Sound engineering tradeoffs

You are **not** expected to implement everything.

---

## Deliverables

### Source Code

Provide the project in a Git repository.

### README

Include:

- How to run the project
- Assumptions you made
- Tradeoffs you intentionally chose
- What you would improve with another day of work

---

## Optional

Include a **5–10 minute screen recording** covering:

- What you built
- Why you made your design decisions
- What you'd improve with more time
- Anything you're particularly proud of

---

## Goal

Build the first iteration of an application that another team could continue developing.

The technical discussion will focus on your engineering decisions, tradeoffs, and how the project could evolve over time—not whether you implemented every possible feature.
